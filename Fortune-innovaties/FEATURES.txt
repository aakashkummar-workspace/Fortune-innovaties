  ============================================================
  FORTUNE INNOVATIVES — COMPLETE FEATURE & LOGIN GUIDE
  ============================================================

  A multi-tenant, multi-branch educational institute management platform
  combining lead acquisition, telecaller workflow, admissions, fee tracking,
  academic delivery (batches, attendance, LMS), placement, payroll,
  performance analytics, and operational settings.

  Frontend:   https://crm.fortuneinnovatives.com
  Backend API: https://api.fortuneinnovatives.in
  Database:   PostgreSQL on Supabase
  Auth:       JWT (role + branch claims)
  Messaging:  WhatsApp via Evolution API (message.sirahagents.com)

  1.3 ROLE HIERARCHY
  ------------------------------------------------------------
  Role               Code                Scope                                Created by
  CEO                CEO                 Org-wide, all branches               Setup wizard (first run)
  Admin              ADMIN               Org-wide ops                         CEO
  Channel Partner    CHANNEL_PARTNER     One or more branches                 CEO / Admin
  Trainer            TRAINER             Assigned batches                     CEO / Admin / CP
  Telecaller         TELECALLER          Branch-visible leads + own leads     CEO / Admin / CP
  Student            STUDENT             Self only                            Auto-created on Admission -> Student conversion


  1.4 PASSWORD MANAGEMENT
  ------------------------------------------------------------
  - Self password change: Profile -> Change Password (current + new + confirm).
  - Admin/CEO reset: Users page -> row -> Reset Password -> system generates a
    temporary password and shows it once. User must change it after first login.
  - Forgot password: No public flow — user must contact the CEO/Admin to reset.


  1.5 SESSION & LOGOUT
  ------------------------------------------------------------
  - JWT token stored in localStorage (auth_token).
  - Token includes: user id, role, branchId, assignedBranches.
  - Logout clears the token + redirects to /login.
  - Token expiry triggers automatic logout on next API call.

  /telecaller/dashboard               Telecaller Dashboard       Detailed

  ============================================================
  PART 3 — CROSS-CUTTING FEATURES
  ============================================================

  3.1 NOTIFICATIONS (all logged-in users)
  ------------------------------------------------------------
  - Bell icon in top bar with unread count.
  - Categories per role:
    * CEO / Admin / CP — lead activity, admission, fee approval needed,
      task assigned, system alerts.
    * Trainer — new student in batch, portfolio submission, task assigned,
      attendance approval.
    * Telecaller — new lead assigned, follow-up due, WhatsApp delivered/failed.
    * Student — fee due, class today, portfolio task assigned, test scheduled.
  - Deep-linking — each notification clicks through to the exact page +
    tab + scrolled position. E.g., "Task Added" -> /payroll?tab=tasks and
    auto-scrolls to the task list.


  3.2 WHATSAPP INTEGRATION
  ------------------------------------------------------------
  - Evolution API instance "Fortune" at message.sirahagents.com.
  - Auto-triggered messages:
    * Welcome on lead creation (manual creation only — bulk upload is silent)
    * Follow-up reminders
    * Fee reminders
    * Demo invites
  - WhatsAppLog — every send recorded with status (sent, delivered, failed).
  - Manual send — telecaller can send a templated WhatsApp from the lead view.


  3.3 MULTI-BRANCH SUPPORT
  ------------------------------------------------------------
  - Branches have name, code, address, lat/long, geofence radius, totalLeads
    counter, optional rating toggle.
  - Users can be primary-assigned to one branch + secondary-assigned to many
    (assignedBranches).
  - All queries auto-scope by branch via enforceBranchAccess middleware.


  3.4 AUTO-BACKFILL / SELF-HEALING
  ------------------------------------------------------------
  - Server boot runs idempotent backfills:
    * Conductor trainers (CP/CEO with TRAINER capability).
    * Notification links (deep-link paths set on legacy notifications).
  - Raw-SQL fallback pattern for schema fields not yet in regenerated Prisma
    client.

  is still findable.
